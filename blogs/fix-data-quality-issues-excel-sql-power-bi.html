From Messy Data to Clear Insights: How to Find and Fix Data Quality Issues

A polished dashboard can still lead to the wrong decision if its underlying data is incomplete, duplicated or inconsistent. Before calculating revenue, comparing regions or presenting trends, an analyst needs to establish whether the dataset can be trusted.

Data quality work is not simply deleting blank cells. It means identifying issues, understanding their source, applying transparent rules and checking that the cleaned data still represents the business accurately. This guide walks through a repeatable workflow using Excel, SQL and Power BI.

Why data quality matters

Imagine a retailer receives sales records from several branches. One branch records a region as “North Zone”, another uses “north zone”, and a third uses “N Zone”. Some orders appear twice after a file import, while a few transaction dates are blank. If these issues are ignored, regional totals may be split incorrectly, sales may be overstated and monthly reporting may become unreliable.

Useful data quality dimensions include accuracy, completeness, consistency, validity, uniqueness and timeliness. Which dimension matters most depends on the business question. A missing customer age may not affect a sales total, while a missing order date can make monthly analysis impossible.

Step 1: Understand the dataset before changing it

Document what each row represents and what each field means. A sales dataset might contain order_id, order_date, customer_id, region, product, quantity, unit_price and order_status.

  • Confirm the expected grain: one row per order, order line or customer.
  • Check column names, data types, date ranges and units.
  • Identify required fields and optional fields.
  • Ask the data owner how cancellations, refunds and returns are recorded.
  • Keep an untouched copy of the original data for traceability.

Do not remove every blank or unusual value immediately. First decide whether it is an error, a valid exception or information that needs clarification.

Step 2: Find common issues in Excel

Excel is a practical starting point for profiling a small or medium-sized dataset. Convert the range into a table, enable filters and inspect each column.

Missing values

Filter important columns for blanks or use =COUNTBLANK(Table1[order_date]) to count missing dates. Correct a value only from a reliable source. Otherwise, mark it as unknown or exclude it from a particular calculation with the limitation documented. Never fill blanks with arbitrary values just to make a sheet look complete.

Duplicate records

Use conditional formatting or Remove Duplicates to investigate repeated rows. First define the unique key. Two order lines can share an order ID and still be legitimate if an order contains multiple products. Define duplicates using the business grain, not one convenient column.

Inconsistent formats

Functions such as TRIM, CLEAN, UPPER and PROPER can help standardise text after you decide on a convention. Check dates stored as text, numbers stored as text and currency values using different units.

Step 3: Use SQL for repeatable quality checks

SQL makes it easier to profile larger tables and repeat checks after each refresh. These examples use a simplified sales table; adapt names and rules to your database.

Find missing values

SELECT
  COUNT(*) AS total_rows,
  SUM(CASE WHEN order_id IS NULL THEN 1 ELSE 0 END) AS missing_order_ids,
  SUM(CASE WHEN order_date IS NULL THEN 1 ELSE 0 END) AS missing_order_dates,
  SUM(CASE WHEN customer_id IS NULL THEN 1 ELSE 0 END) AS missing_customer_ids
FROM sales;

Check possible duplicate order lines

SELECT order_id, product_id, COUNT(*) AS record_count
FROM sales
GROUP BY order_id, product_id
HAVING COUNT(*) > 1;

This check is appropriate only if the business confirms that an order can contain a product once. If repeated product lines are allowed, include the actual line identifier or another suitable key.

Find values outside expected rules

SELECT *
FROM sales
WHERE quantity <= 0
   OR unit_price < 0
   OR order_date > CURRENT_DATE;

These are examples, not universal rules. Negative quantities or prices may represent valid returns or adjustments. Confirm the data model before labelling records as errors.

Step 4: Create a documented cleaning process

Maintain an issue log containing the column, issue type, affected record count, business impact, agreed treatment and validation result. This makes the process reviewable and repeatable.

  • Correct formatting problems using consistent, documented rules.
  • Resolve missing critical values from an authoritative source where possible.
  • Quarantine records that cannot be safely corrected instead of silently deleting them.
  • Remove confirmed duplicates only after defining the correct unique key.
  • Use a mapping table to standardise category variants.
  • Record row counts before and after each transformation.

Distinguish between fixing a value and excluding a record from one analysis. A transaction with a missing date might still be useful for a product count even if it cannot be included in monthly trends.

Step 5: Validate the cleaned data in Power BI

Power Query can support repeatable transformations such as changing data types, trimming text, replacing known category variants and identifying duplicates. Apply transformations in a clear sequence and give each step a meaningful name.

Before building visuals, compare key totals with the source system or an independently calculated SQL result. Check whether joins multiply rows unexpectedly, relationships use the intended keys and filters produce sensible totals. A dashboard should make important data limitations visible.

Useful quality indicators include the percentage of records with valid dates, missing required identifiers, confirmed duplicate keys, values outside agreed ranges and the last successful refresh date.

Step 6: Turn the workflow into a portfolio project

Use a fictional retail dataset with deliberately introduced issues: inconsistent region names, duplicate rows, missing dates and invalid quantities. Show how you investigated and handled each issue.

  1. Business context: explain why accurate regional sales reporting matters.
  2. Data profiling: show initial row counts, column types and an issue summary.
  3. Excel checks: document missing-value, duplicate and formatting checks.
  4. SQL validation: include queries for nulls, duplicate keys and rule violations.
  5. Power Query workflow: show the transformations and their order.
  6. Final report: present sales insights alongside data quality indicators.
  7. Reflection: explain which records were corrected, excluded or left unresolved, and why.

Use public or synthetic data and never publish private customer or business information. Include a README explaining assumptions so another person can reproduce the work.

Final takeaway

Reliable analysis begins before the first chart. Understand the dataset, define business rules, profile records, document corrections and validate the output. Excel helps with quick inspection, SQL supports repeatable checks and Power BI helps create a transparent reporting workflow.
