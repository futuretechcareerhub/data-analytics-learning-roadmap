Why Are Customers Clicking but Not Buying? A Data Analytics Investigation of the Conversion Gap

A website can attract plenty of visitors and still generate very few orders. Learn how a data analyst traces the conversion journey, finds the biggest drop-off and turns evidence into practical improvements.

Published: November 16, 2026   •   9–11 min read

Imagine an online store receiving 20,000 visits in a month. Product pages are being viewed, advertisements are getting clicks and visitors are adding items to their carts. Yet completed purchases remain lower than the business expected. The immediate assumption might be that the website needs more traffic, but the real issue could be hiding inside the customer journey.

This is a useful business problem for anyone learning Data Analytics training in India: instead of guessing why sales are weak, an analyst uses event data to identify where visitors leave and which parts of the journey need attention.

Case-study question: At which stage do visitors drop out of the purchase journey, and what evidence can help the business improve conversion?

1. Understand the conversion funnel

A conversion funnel breaks a broad customer journey into measurable steps. For an e-commerce website, a simple funnel could look like this:

  1. Visit: a user lands on the website.
  2. Product view: the user opens a product page.
  3. Add to cart: the user expresses purchase intent.
  4. Begin checkout: the user starts entering delivery or payment details.
  5. Purchase: the order is successfully completed.

Each stage should have a clear event definition. For example, count unique visitors rather than raw page views when measuring how many people reached a stage. Also decide how the analysis handles repeat sessions, logged-out users and visitors who return later.

2. Prepare the data in Excel

Start with an event-level dataset. Each row may represent an action performed by a visitor. Useful fields include visitor ID, session ID, event name, event timestamp, device type, traffic source, landing page and order ID.

In Excel, check for blank visitor IDs, duplicate event records, inconsistent event names, invalid timestamps and missing device or source values. Standardise labels such as “mobile”, “Mobile” and “MOBILE” so they are not treated as separate categories.

Use PivotTables to count distinct visitors at each stage where supported, or create a deduplicated visitor-stage table first. A basic stage conversion rate is:

Stage Conversion Rate = Visitors Reaching Next Stage
                        / Visitors Reaching Current Stage

Stage Drop-off Rate = 1 - Stage Conversion Rate

Keep the denominator visible in every report. A percentage without its underlying visitor count can be misleading, especially for small segments.

3. Use SQL to measure funnel movement

SQL helps transform event records into a consistent funnel summary. The following example assumes the table contains one row per recorded event and that the analysis window has already been selected.

WITH visitor_stages AS (
  SELECT
    visitor_id,
    MAX(CASE WHEN event_name = 'product_view' THEN 1 ELSE 0 END) AS viewed,
    MAX(CASE WHEN event_name = 'add_to_cart' THEN 1 ELSE 0 END) AS carted,
    MAX(CASE WHEN event_name = 'begin_checkout' THEN 1 ELSE 0 END) AS checked_out,
    MAX(CASE WHEN event_name = 'purchase' THEN 1 ELSE 0 END) AS purchased
  FROM website_events
  GROUP BY visitor_id
)
SELECT
  SUM(viewed) AS product_viewers,
  SUM(carted) AS cart_visitors,
  SUM(checked_out) AS checkout_visitors,
  SUM(purchased) AS purchasers,
  ROUND(100.0 * SUM(carted) / NULLIF(SUM(viewed), 0), 2) AS view_to_cart_pct,
  ROUND(100.0 * SUM(checked_out) / NULLIF(SUM(carted), 0), 2) AS cart_to_checkout_pct,
  ROUND(100.0 * SUM(purchased) / NULLIF(SUM(checked_out), 0), 2) AS checkout_to_purchase_pct
FROM visitor_stages;

This is a simplified visitor-level funnel. In a production analysis, define a session or conversion window, ensure events occur in the correct order, handle multiple purchases and decide how to attribute visitors who use multiple devices. Otherwise, a visitor who purchased before viewing a product in the selected period could distort the result.

4. Find the segment with the largest conversion gap

An overall conversion rate tells only part of the story. Break the funnel down by dimensions that may explain different experiences:

  • Device: mobile, desktop and tablet.
  • Traffic source: organic search, paid search, social, referral and email.
  • Landing page: campaign pages, category pages and product pages.
  • New versus returning visitors: compare journey patterns for each group.
  • Geography or browser: check only when the data is reliable and privacy rules permit it.

For example, suppose mobile visitors add products to their carts at a healthy rate but rarely complete checkout, while desktop visitors complete purchases more often. That pattern suggests a checkout experience worth investigating on mobile. It does not prove the mobile layout is the cause; payment errors, shipping costs, page speed and audience differences are alternative explanations to test.

5. Build a Power BI conversion dashboard

Power BI can bring the funnel and its segments into one interactive view. A useful report can include:

  • KPI cards for unique visitors, cart visitors, purchasers and overall conversion rate.
  • A funnel visual showing visitor counts at each stage.
  • A bar chart comparing conversion rates by device and traffic source.
  • A trend chart showing conversion rate by day or week.
  • A detail table showing landing page, visitors, purchases and conversion rate.
  • Slicers for date range, device, source and new or returning visitor type.

Keep the dashboard focused on decisions. Label each metric, show the reporting period, display sample sizes and make it easy to compare segments. Avoid mixing session-based and visitor-based metrics in the same visual without clearly explaining the difference.

6. Turn findings into testable recommendations

Analytics should lead to a question or action, not just a chart. If the largest drop occurs between checkout start and purchase, the team can investigate:

  • Whether unexpected delivery fees appear late in checkout.
  • Whether the payment step has errors or limited payment choices.
  • Whether forms are difficult to complete on smaller screens.
  • Whether account creation is required before purchase.
  • Whether page speed or technical failures affect particular devices.

Prioritise recommendations by expected impact, confidence in the evidence and implementation effort. Where possible, run an A/B test with a defined success metric and guardrail metrics such as refunds, average order value and payment failure rate. Compare results over an appropriate period and avoid declaring a winner from a very small sample.

7. What skills does this project demonstrate?

A well-documented conversion-gap project can demonstrate several practical analytics skills:

  • Excel data cleaning, validation and PivotTable analysis.
  • SQL aggregation, conditional logic, grouping and rate calculations.
  • Power BI data modelling, measures, filters and dashboard design.
  • Funnel analysis, segmentation and metric definition.
  • Business communication: explaining what the data shows, what remains uncertain and what should be tested next.

For a portfolio, include the business question, dataset description, cleaning decisions, SQL queries, dashboard screenshots, key findings and recommended experiments. Clearly label any sample or simulated data; never present invented results as actual company performance.

Conclusion

When customers click but do not buy, the answer is rarely found by looking at traffic totals alone. A structured funnel analysis helps reveal where the journey weakens, while segmentation provides clues about which users or experiences need investigation. Excel, SQL and Power BI work together to turn raw website events into a clear, testable business story.

Practising projects like this helps learners connect technical tools with real business questions—the kind of problem-solving expected in practical analytics work.
