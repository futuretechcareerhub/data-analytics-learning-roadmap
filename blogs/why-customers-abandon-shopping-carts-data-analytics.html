Why Do Customers Abandon Their Shopping Carts? A Data Analytics Investigation

A practical e-commerce case study using Excel, SQL and Power BI to find where shoppers leave and what a business can investigate next.

Home | All Data Analytics Blogs

Published: November 2, 2026

An online store may attract visitors, receive product views and add-to-cart activity, yet still miss its sales target. One possible reason is that shoppers leave before completing checkout. A high cart abandonment rate is a signal to investigate—not proof of one particular problem.

In this practical data analytics investigation, we will follow the customer journey from cart creation to completed purchase. We will use Excel to validate the data, SQL to locate drop-off patterns and Power BI to communicate findings. The goal is to turn a broad concern into specific, testable business questions.

1. Define the business question before analysing data

Start with a clear question: At which stage of the shopping journey are eligible shoppers leaving, and which segments show the largest differences?

Map the journey into measurable events, such as:

  • Product view: a shopper views a product.
  • Add to cart: a product is added to a cart.
  • Checkout started: the shopper begins checkout.
  • Payment attempted: a payment attempt is recorded.
  • Purchase completed: a valid order is confirmed.

Agree on the unit of analysis. A session-based funnel answers a different question from a cart-based or user-based funnel. Also define the observation window, timezone, treatment of repeat visits and what counts as a completed order before calculating a rate.

2. Prepare and validate the data in Excel

A useful practice dataset may contain cart ID, customer ID, session ID, event name, event timestamp, product category, device type, traffic source, cart value, shipping charge, discount, payment method and order status. Keep personally identifying information out of a learning dataset.

In Excel, check:

  • Duplicate event IDs and repeated records.
  • Missing cart, session or timestamp values.
  • Inconsistent event names and category labels.
  • Events that appear in an impossible order, such as a purchase timestamp earlier than checkout.
  • Test orders, cancelled orders and failed payment attempts that need separate treatment.
  • Whether cart value and order value use the same currency and tax/shipping rules.

Use filters, conditional formatting, PivotTables and lookup functions to inspect records and compare event counts. Document every exclusion so another analyst can reproduce the result.

3. Use SQL to find where shoppers drop off

Once the event data is consistent, SQL can summarise the funnel. The example below assumes one row per recorded event in a table named shopping_events. Adapt column names and the definition of a session to the actual dataset.

WITH session_steps AS (
  SELECT
    session_id,
    MAX(CASE WHEN event_name = 'add_to_cart'
             THEN 1 ELSE 0 END) AS added_to_cart,
    MAX(CASE WHEN event_name = 'checkout_started'
             THEN 1 ELSE 0 END) AS checkout_started,
    MAX(CASE WHEN event_name = 'payment_attempted'
             THEN 1 ELSE 0 END) AS payment_attempted,
    MAX(CASE WHEN event_name = 'purchase_completed'
             THEN 1 ELSE 0 END) AS purchased
  FROM shopping_events
  WHERE event_timestamp >= '2026-10-01'
    AND event_timestamp < '2026-11-01'
  GROUP BY session_id
)
SELECT
  COUNT(*) AS sessions,
  SUM(added_to_cart) AS cart_sessions,
  SUM(checkout_started) AS checkout_sessions,
  SUM(payment_attempted) AS payment_sessions,
  SUM(purchased) AS purchase_sessions
FROM session_steps
WHERE added_to_cart = 1;

This query creates a simple session-level view. In a production analysis, verify that events belong to the same session and that a purchase is correctly attributed to the relevant cart. If the business question is specifically about carts, use a stable cart ID rather than assuming session ID and cart ID are interchangeable.

4. Calculate the right metrics

For a defined population and time window, a basic cart abandonment rate can be expressed as:

Cart abandonment rate = (Eligible carts − Purchased carts) ÷ Eligible carts × 100

State what “eligible cart” means. For example, exclude internal test activity and decide how to handle duplicate carts, expired carts and purchases completed in a later session. Do not compare rates calculated with different definitions.

Useful supporting metrics include:

  • Checkout initiation rate: checkout-started carts divided by eligible carts.
  • Checkout completion rate: completed purchases divided by checkout-started carts.
  • Payment failure rate: failed payment attempts divided by payment attempts.
  • Time to purchase: elapsed time between the selected starting event and purchase.
  • Abandoned cart value: the value of eligible carts without a matched purchase, using a clearly documented valuation rule.

A funnel is not automatically a causal explanation. A lower conversion rate on one device or traffic source identifies a pattern to investigate; it does not prove that the device or source caused abandonment.

5. Segment the results to uncover useful patterns

Compare abandonment and stage-to-stage conversion by:

  • Device: mobile, desktop and tablet.
  • Traffic source: organic search, paid campaigns, email and referral.
  • Product category: categories with different prices, delivery needs or purchase consideration.
  • Cart value: value bands that may reveal sensitivity to shipping or total cost.
  • Payment method: where enough reliable payment-attempt data is available.
  • New versus returning shoppers: using a consistent customer definition.

Check sample sizes alongside percentages. A segment with very few carts can show a volatile rate. Compare equivalent periods and account for promotions, seasonality, stock availability and changes in campaign mix.

6. Build a decision-ready Power BI dashboard

A focused dashboard should help an e-commerce manager move from “cart abandonment is high” to “which stage and segment should we investigate first?” Consider these visuals:

  • KPI cards: eligible carts, purchased carts, abandonment rate and checkout completion rate.
  • Funnel visual: cart, checkout, payment and purchase counts.
  • Bar chart: abandonment rate by device, category or traffic source.
  • Trend line: daily or weekly abandonment rate with a consistent definition.
  • Detail table: segment, eligible cart count, purchase count, rate and sample size.
  • Slicers: date range, device, traffic source and category.

Display the reporting period, metric definitions and data refresh date. Make sure filters affect all relevant visuals consistently, and reconcile dashboard totals with the SQL output before sharing.

7. Turn patterns into hypotheses and next steps

Use the evidence to decide what to test—not to jump straight to a conclusion. Examples include:

  • If mobile checkout has a lower completion rate, review page speed, form usability and error logs on mobile devices.
  • If many shoppers leave after shipping costs appear, test clearer delivery-cost information earlier in the journey.
  • If payment attempts fail more often for one method, review payment-provider responses and technical errors.
  • If a product category has unusually high abandonment, check stock availability, delivery estimates, product information and pricing.

Prioritise issues by potential business impact, confidence in the data, effort and customer experience. Where possible, run a controlled experiment and compare results against a pre-defined success metric. Monitor guardrails such as refunds, cancellations and support contacts so a short-term conversion gain does not hide a wider problem.

8. Make it a portfolio-ready data analytics project

To present this work as a portfolio case study, include:

  1. A short business problem statement and clearly defined funnel.
  2. A data dictionary and notes on cleaning decisions.
  3. Excel validation evidence and SQL queries.
  4. A Power BI dashboard with metric definitions.
  5. Three to five evidence-backed observations, with sample sizes.
  6. Prioritised recommendations and a proposed experiment.
  7. A limitations section explaining attribution, missing events and assumptions.

Never invent results to make the project look impressive. If you use synthetic data, label it clearly and describe the findings as a demonstration rather than real customer behaviour.

Conclusion

Shopping cart abandonment is a useful case study because it combines event data, metric definitions, segmentation and business decision-making. Excel helps establish data quality, SQL reveals where the journey changes and Power BI makes the patterns easier to discuss. The most valuable outcome is not simply a percentage—it is a transparent analysis that helps a team decide what to investigate and test next.
